The six steps

In this order. Each one has a test you can run yourself, so you never have to take my word for it that something works.

01

Morning brief

Done ✓

Reads your trading rules and the trading_open items from your checklist, puts them into one message, and sends it to you on Telegram. Your wording is printed exactly as stored. Nothing is reordered or improved.

A different lock, and a stranger check Telegram cannot send the password the schedule uses, so this function uses Telegram's own: a secret handed over when the webhook is registered, which Telegram returns on every message. And anyone who finds your bot can message it, so a message from any chat but yours is dropped without being saved and without a reply, because replying would tell them the bot is listening.
Proven
14 Sep 2026. The message arrived on his phone. Six rules numbered 1 to 6 and five checklist items with empty boxes, in his own words.
How
43 checks against the code, then the schema run against a real PostgreSQL 16, then his real rows fed through the real message code and compared character for character.
Open
His checklist has five items where two documents say six. Left visible rather than filled in.
What it cost to get here Seven separate faults, each one found from evidence rather than guessed at: the wrong kind of Supabase key for the door check, a secret named with the wrong capital letters, a database key stored under a name this project no longer uses, a database with none of the tables in it, an unclosed quote mark that meant the command never ran at all. Every one of them was named by the app itself or by a query, not by trial and error.
02

The schedule

Done ✓

Sends the brief at 8:10 every morning without you asking. It fires at 12:10 and 13:10 GMT and the code throws away whichever one is not your 8:10, so the clocks changing needs nothing from you, ever.

Verified
Walked across 365 consecutive days: every one sends exactly once, never twice, never none. Both clock-change days checked by name. The job itself read back out of the database rather than off a form: switched on, both headers present, the key exactly 64 valid characters, twenty second timeout.
Proven
15 Sep 2026, 8:10am. One message, on its own. The scheduler had never once called the function before that moment. It has now.
Settled: the clocks Supabase counts in GMT. 8:10 in New Jersey is 12:10 GMT in summer and 13:10 GMT in winter, and a schedule does not move itself when the clocks change. Rather than ask you to edit a line twice a year and remember to, both moments fire and the code decides. You never touch this again, in November, in March, or if the rules about clocks ever change.

The privacy rules

Hard requirements, not preferences. These are the reason the app is shaped the way it is.

Your private thoughts, your income situation and your business arrangements are not going to be used to train anybody's model.
1No AI request leaves this app. None.Not Gemini, not OpenAI, not Anthropic. There is a check that fails on purpose if any code path ever tries to reach one, so this cannot be added by accident later.
2The private flag is load bearingIf AI is ever turned on, the check for it goes in before the outbound request, never after.
3No secret is ever written into a fileBot token and keys live in Supabase's own secret storage. A file that ignores .env went in first, before any code.
4The tables are locked to everyoneDeliberately. The public key can read and write nothing at all. Only code holding the private key gets in. If something cannot read the database, it is holding the wrong key, and the answer is never to unlock the table.
5Turning AI on is your decision, laterAnd it would be a paid tier, because free tiers generally reserve the right to train on what you send them.

Settled, and not up for discussion

Decided after a full review. Recorded here so no future session reopens them.

×No n8nA local install cannot fire a 7am brief while the laptop is asleep, and the cloud version has no permanent free tier. This is one database talking to one chat app, which is code, not plumbing.
×No React Native or ExpoTelegram is the interface. A PWA is the fallback if a real app is ever wanted.
×No local AI modelA 2019 Intel Mac runs them slowly and badly.
×No WhisperThe iPhone keyboard already has a dictation mic. Speak into Telegram and it arrives as text.
✓Supabase for all of itDatabase, the small programs, and the scheduling. One free tier, one place, nothing to keep alive.
✓Trading stays deliberately dumbRules and checklist, read out verbatim. No market data, no trade records, no analysis. You have two other tools for that.

Words I will keep using

So none of them ever need explaining twice.

Function
One small program Supabase runs for you when something asks it to. It is not running all the time and there is no server of yours to keep alive.
Deploy
Putting code somewhere it can actually run. Until then it is just a document in a folder.
Secret
A password-like string, such as your bot token. Stored by Supabase, never written into a file.
Storage area
A folder on GitHub that keeps every version of your files, so nothing is ever lost by overwriting it.
Branch
A parallel copy of that folder. Work happens on one so the main copy stays untouched until you are happy.
Cron
A clock that runs something on a schedule. Yours counts time in UTC, not Eastern.
Dry run
Asking the code to build the message and show it to you without sending it.
Row
One entry in a table. One trading rule is one row.
Private project. Nothing here is shared and no AI service is contacted by any part of it.
